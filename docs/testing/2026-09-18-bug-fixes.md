## 不作盲目修改的条目

- **2、3**：已有修复，本轮未重复改写；现有回归随完整 Rust 测试执行。
- **6**：`unapply_project` 当前 UI 没有调用。保留旧 IPC 语义，本轮未重构。报告所称“已不存在的文件仍出现在列表”不准确，列表先扫描真实目录；残留 managed_entries 与部分成功的风险仍存在。正常 UI 停用项目走事务性的 `set_project_enabled`。
- **14 的其他旧 IPC**：旧 unregister/apply_group/unapply 路径未统一重构为跨文件事务；其中部分没有当前 UI 调用。不要把本轮注册修复理解成所有 mutate 回调都获得文件系统回滚能力。
- **10 的附带清理建议**：没有批量删除 provenance/active_groups/managed_entries 等记录。这些包含来源和文件所有权信息，不能仅凭扫描缺失就一起丢弃；备注计数等低影响问题也未扩大到本轮。
- **4 的绝对化描述**：“所有密码服务器必然无法连接”不准确，实际是消息到达时序相关；已复现并修复这一竞态。
- **18 的原触发解释**：断线只标记 disconnected，不会自动切回本机；未找到跨窗口目标同步。修复依据是实际存在的 await 前后目标绑定问题。
- **sourceIds 空数组**：并非后端恒发空数组。正常来源生成有 studio/unknown/external 等兜底，且未开启来源筛选时不会因此隐藏卡片；没有按报告修改来源归属规则。
- **copyStale 的提示样式**：重新复制按钮和状态提示已有，是否加红色背景属于提示策略，未把它作为功能故障修改。
- **只读目录、超长文件名、非 UTF-8 名称、手改非法配置、极端回滚权限错误**：未建立当前用户路径的复现，不做推测性重构。
- **监控范围、扫描次数、远端刷新全部 query**：保留为性能测量项，本轮不凭复杂度描述改动监听和缓存策略。
- **死代码、图标尺寸、文档计数、IPC 测试扫描范围**：属于清理或测试覆盖改进，本轮未扩展为全项目整理。
